# Learning Space 0.7 — phone and coaching

The phone now renders a dedicated React presentation, with shared storage/domain logic. It remains an offline Android WebView app, rather than a Kotlin/Compose rewrite. The app has no native utility toolbar; the WebView sits beneath the Android system bar. System typography, a four-tab bottom bar, generous touch targets, full-screen import/course/session sheets, and a quieter profile entry into Settings replace the desktop sidebar and compact header.

Today focuses on time recorded, a daily target and a recommended next block. Library uses readable rows and course/book covers, searchable lessons, type chips and learning areas. Coach provides conversation, explicit editable memory and session reviews. Progress uses real logs, timezone-based streaks, a weekly chart and linked learning goals. Widgets and Wi-Fi pairing remain in Settings alongside the AI connection and backups. Desktop uses its existing wider dashboard.

Google's official [Fitbit preview](https://blog.google/products-and-platforms/devices/fitbit/personal-health-coach-public-preview/) describes timely insights after activity, recommendations informed by recent activity, and feedback informing future suggestions. The [Google Health app overview](https://blog.google/products-and-platforms/products/google-health/google-health-app/) describes four primary tabs and coach insights in Today. We adapt those interaction patterns; we have no knowledge of their proprietary prompts or event pipeline.

A saved session records selected material, reported time, planned block, timer as context, optional difficulty/reflection, goal alignment and the recommendation before logging. A local review appears immediately, including honest priority tradeoffs and a concrete next step. It never claims verified comprehension. Completion through the shortcut is explicitly labelled estimated time. Session IDs protect duplicate saves. Undoing a lesson removes its associated logs and reviews. At most 120 reviews are kept; original PDFs and keys are excluded from backups.

AI reviews are opt-in in Settings and use the existing personal-key connection. Only sessions logged with the switch enabled enter the queue. The foreground worker processes one at a time, with visible pending/error/retry states; app reopen resumes queued work, and errors do not retry automatically. Turning the feature off stops new scheduling. An already-sent request may still return. The request includes session evidence and bounded goals/activity/library metadata; general notes are excluded. A reflection is deliberately included. Each request uses API credit and needs internet. A successful response is validated against supplied resource references. Proposed changes stay behind an explicit Preview/Apply flow. The follow-up conversation includes the review context; offline follow-up reuses the recorded assessment rather than pretending to be a model.

Validation includes domain and protocol tests for pre-session snapshots, priority detours, unverified understanding, logging/estimates, duplicate/invalid saves, retention, serialization, independent Wi-Fi sessions, old-client preservation and shared native/hosted AI input. Browser QA covers 390px/320px and desktop, light/dark, navigation, imports, sessions and contextual follow-up. The APK compiles and its signature and native storage/widget checks pass. A physical Samsung/One UI runtime and live AI generation require a device and a configured key; they are not represented by browser previews.
